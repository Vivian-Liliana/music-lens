# 新手操作指南：让 AI "读" 懂一首歌

> 不需要显卡，不需要 API key，不需要联网（装好之后）。全程本地跑。
> 适用对象：会复制粘贴命令、但没写过代码的人。

---

## 先说结论：它能干什么

给它一个音频文件，它给你六样东西：

| 输出 | 内容 |
|---|---|
| 歌词 + 时间轴 | `[02:15] 这一句唱的是什么` |
| 响度曲线 | 哪一段安静、哪一段炸 |
| 音色亮度 | 偏暗暖、还是偏尖亮 |
| 调性 | 比如 C minor（小调，偏忧郁） |
| 速度 | BPM |
| 段落结构 | 前奏 / 主歌 / 副歌 的位置 |

**它不能干什么**：判断"这首歌好不好听"、"伤不伤感"。这些它给不出可靠答案，别指望。

---

## 准备

- 一台 Windows 10/11 电脑（Mac / Linux 也能用，只是安装命令不同）
- 大约 10 分钟
- 一个音频文件：`.mp3` / `.flac` / `.wav` / `.m4a`
- 磁盘留 2 GB

**不需要**：显卡、微软账号、任何付费服务。

---

## 三步装好

### 第 1 步：装 Node.js

打开 https://nodejs.org/ ，下载 LTS 版，一路下一步。

装完**新开一个 PowerShell 窗口**（这点很重要，旧窗口读不到新的环境变量），输入：

```powershell
node -v
```

看到 `v22.x` 或 `v24.x` 就对了。

### 第 2 步：装 music-lens

```powershell
npm i -g music-lens
```

如果报 `禁止运行脚本` 或 `无法加载 npm.ps1`，说明 Windows 的执行策略把脚本拦了。执行这一条解锁：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 第 3 步：初始化（装依赖 + 下模型）

```powershell
music-lens setup
```

这一步会：
1. 检查有没有 Python，没有就用 winget 自动装
2. 装 6 个 Python 库（约 500 MB）
3. 从镜像下载语音模型（461 MB）

**十分钟左右，看着它跑就行。** 中途会刷很多行日志，正常。

装完跑一下体检：

```powershell
music-lens doctor
```

期望看到三行 `ok` 和两个模型路径。有一项 `MISSING` 就重跑一次 `setup`。

## 第一次分析

```powershell
music-lens analyze "C:\music\某首歌.mp3"
```

默认用 `small` 模型。一首 4 分钟的歌，CPU 上大约 2–4 分钟。

跑完在当前目录（或 `--out` 指定的地方）生成一个文件夹，里面有六个文件。**先看 `00_summary.md`**，那是给人读的，其他五个是给程序和图表用的。

---

## 关键：唱歌必须先分轨

这是整个流程里最容易忽略、又最影响结果的一步。

**原曲直接喂给识别模型，歌词基本是瞎猜。** 因为伴奏会和人声混在一起，模型分不清哪个是人在唱。

正确做法是先用 demucs 把伴奏剥掉：

```powershell
music-lens separate "C:\music\某首歌.mp3"
```

它会生成 `stems\htdemucs\某首歌\vocals.wav`（人声）和 `no_vocals.wav`（伴奏）。然后：

```powershell
music-lens analyze "...\vocals.wav" --model medium
```

**分轨 2 分钟，效果差一个量级。** 值。

## 它能到什么程度（实测）

| 素材 | 结果 |
|---|---|
| 纯语音（讲座、播客、有声书） | ✅ 几乎完美，错字很少 |
| 录音室制作的歌曲 | ✅ 分轨后歌词连贯，能看出主歌副歌 |
| 现场录音 / 合唱 / 混响很重 | ❌ 文字基本不可用，还会编出奇怪的句子 |

**这条最重要：不是所有歌都能做。** 手机在教室里录的合唱、演唱会现场、KTV 录音，别抱期望。
原因很简单——人声被混响和别的声部糊住了，模型没有可分离的信号，谁来做都一样。

## 七个坑（提前知道能省一晚上）

### 1. `npm i -g` 之后命令找不到

npm 生成的 `.ps1` 被执行策略拦住。两个解法：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`（推荐，一次性），或者删掉那个 `.ps1` 文件。

### 2. 下载模型时卡住 / 报 401

`huggingface.co` 在国内经常不通。工具已经自动改用 `hf-mirror.com`，但新版下载器会走 `xet` 通道，对镜像返回 401。
本项目的做法是**直接按 URL 下载**（见 `scripts/get-model.ps1`），绕开这层。如果 `setup` 在这步失败，手动跑：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\get-model.ps1 -Name small
```

### 3. PyPI 镜像 403

清华源对某些请求返回 403。**用官方源就行**，慢一点但通。

### 4. `PyAV 19` 与 `faster-whisper` 不兼容

报 `open() got an unexpected keyword argument 'metadata_errors'`。
本项目已经绕开：用 librosa 自己解码成 16 kHz 数组再喂给模型，不经过 PyAV。

### 5. 歌词里冒出"作詞 李宗盛""中文字幕组"

模型在**没有人声的段落**硬编句子——它在训练数据里见过大量字幕文件，会照着抄。
解法：先分轨（大部分幻觉来自伴奏段），再开 VAD 之外不要给 `initial_prompt`。

### 6. `--lang zh` 会把英文歌硬翻成中文

强制指定语言时，模型会把听不懂的部分"翻译"成中文，出乱码。
**用 `--lang auto`**（现在默认就是 auto）。

### 7. VAD 在音乐上会把人声整段滤掉

语音活动检测是为说话设计的，唱歌的持续音会被判成"非语音"。
所以本工具默认**关闭** VAD；处理纯语音（讲座、播客）时再加 `--vad`。

## 常见问题

**Q：一定要 medium 模型吗？**
中文建议 medium（1.46 GB），英文 small（461 MB）就够。下载：

```powershell
music-lens setup --models medium
```

**Q：能批量吗？**
能，`analyze` 是普通命令，套个 PowerShell 循环即可。但每首 2–4 分钟，几十首要跑一下午。

**Q：能分析日文 / 韩文 / 俄文歌吗？**
能，`--lang` 支持 100 种语言。但非英语歌曲的分轨后识别质量会下降，日文可读、韩文中等、俄文中等偏上。**藏语等低资源语言别试**，模型会编。

**Q：会上传我的歌吗？**
不会。全部本地计算，断开网络也能跑。

**Q：结果准吗？**
- 响度、亮度、速度：准
- 调性：大致准，电子乐和离调多的歌会错
- 歌词：好音源准，差音源不可用
- 情绪：**不准，别信**
